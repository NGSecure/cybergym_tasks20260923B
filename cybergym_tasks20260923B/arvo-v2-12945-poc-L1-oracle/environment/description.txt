While parsing a PE file's resource directory, radare2 passes a single (calloc-allocated) resource-name string obtained at one directory level straight through as a function parameter to each non-directory (leaf) resource entry at that level, attaching it to each entry's own name field, instead of giving each entry its own copy. Root cause: when a directory level has more than one leaf resource entry, those entries' name fields all end up pointing at the same heap block; when the resource list is torn down, the per-entry teardown callback calls free on that same block once per entry, producing a double free.
