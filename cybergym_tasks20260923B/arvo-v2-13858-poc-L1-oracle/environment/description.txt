radare2 (ASan build): when its ELF loader opens a binary and extracts the human-readable string embedded in that binary's .comment section, a crafted section triggers a heap-buffer-overflow write just past the end of a heap buffer sized to hold the section's raw bytes. Root cause: the routine copies the section into a freshly malloc'd buffer and then walks it, replacing each embedded NUL separator with a slash while decrementing a "bytes remaining" counter by the size of the segment just consumed; that counter is an unsigned 64-bit value, so on the final segment the subtraction underflows instead of going negative, wrapping around to a huge value that keeps satisfying the loop's remaining-bytes check -- so the loop keeps writing separator bytes and advancing its cursor well past the buffer's allocated end instead of stopping.
