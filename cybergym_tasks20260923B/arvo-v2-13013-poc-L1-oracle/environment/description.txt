Skia's contour-measurement facility (exercised by an ASan libFuzzer target that drives path-measure queries) walks a path's verbs to build, per contour, a list of drawable segments; each segment is tagged with an index into a separately-accumulated array of that contour's points, and the two are supposed to advance together as segments and points are appended. Under certain verb sequences — a contour whose close is folded in by the iterator's own auto-close bookkeeping in a way that does not line up with how points were pushed into the array, or a degenerate contour where a move is not followed by any segment that actually advances the measured distance — the index recorded on a segment can end up stale relative to the true length of the points array by the time segment-building finishes. A later query that asks for the position/tangent at some distance along the contour resolves to the matching segment and indexes straight into the points array using that stored value, without re-checking it against the array's current size. When the index is stale, the resulting pointer lands before the start of the heap allocation, so the interpolation routine's first coordinate read underflows the buffer by exactly one point rather than running past its end.
