radare2 crashes (ASan heap-buffer-overflow read) while parsing a crafted Android DEX file's class-definition data: when resolving a string-table entry, the code trusts a length value decoded from the file and hands off a raw pointer straight into the middle of the loaded binary's own data buffer instead of copying that many bytes into a freshly allocated, independently NUL-terminated buffer. Root cause: the routine used to validate/count the string's length scans forward purely by looking for a terminating NUL byte with no bound tied to the buffer's actual size, so when the DEX bytes at that offset contain no NUL before the end of the underlying file buffer, the scan runs past the buffer's heap allocation and reads one byte out of bounds.
