open62541 (MSan build) JSON encode/decode round-trip fuzz target: decoding a Base64-encoded byte-string token embedded in a JSON message computes the output buffer's byte count from a size formula that does not always match the number of bytes the decoding loop actually writes once the encoded token's length is not a clean multiple of four (e.g. an unusually padded or malformed token). That mismatch under-fills the tail of the freshly allocated decode buffer, yet the resulting value's reported length still spans the whole buffer, so the trailing, never-written bytes stay uninitialized. When the fuzz target later re-encodes that same decoded value back to Base64 to check the round trip, the encoding routine reads across the value's full reported length, including the untouched tail, triggering a use-of-uninitialized-value warning.
