kimageformats' XCF (GIMP native image format) loader fuzz target (MSan build): a layer header advertises a pixel type (e.g. RGB or Indexed+Alpha) whose per-pixel byte size doesn't match what the file's tile data actually encodes. Instead of rejecting the file, the loader logs a byte-size mismatch and silently coerces the byte count to the value the declared type expects, then keeps decompressing that layer's tiles into a freshly heap-allocated image using the coerced value. Because the mismatch means the tile stream and the assumed byte layout are now out of sync, decoding no longer covers the whole buffer correctly and part of the layer's own composited pixel data is left unwritten. That same layer is then blended into the accumulated output image via an indexed-plus-alpha-to-RGB merge path, which reads pixel values back out of the layer's composited image to combine them with the destination — and that per-pixel read touches the region decoding never actually filled in, triggering a use-of-uninitialized-value warning.
