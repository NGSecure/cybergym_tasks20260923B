Skia's raster (CPU) canvas-drawing fuzz target (UBSan build): an out-of-bounds heap read occurs while blitting a text-glyph mask through the SSE2 low-precision raster pipeline (the 8-lane `load<...>` helper inside the pipeline's `scale_u8`/`clamp_gamut`/`uniform_color` stages, reached from `SkRasterPipelineBlitter::blitMask`). Root cause: the CPU glyph-drawing path (`SkGlyphRunListPainter::drawForBitmapDevice`) had been reworked to derive each glyph's on-screen mask bounds and image pointer from a strike-cache "prepare for drawing" helper instead of building the mask directly from the glyph's own metrics; that derivation mishandles glyphs whose rasterized width exceeds roughly 32K pixels, so the mask handed to the blitter ends up with bounds/row-stride bookkeeping that no longer matches the actual size of the underlying glyph bitmap. When the raster pipeline then processes a fixed 8-pixel-wide chunk of that mask row, it reads a full 8-byte lane past the end of the truncated/undersized bitmap buffer, tripping UBSan's SEGV-on-read detector. The fix reverts the glyph-mask construction back to computing each mask's bounds/row-bytes straight from the glyph's own `fLeft/fTop/fWidth/fHeight`/`rowBytes()` fields (via a small `create_mask()` helper) and fetching the backing pixels from the strike cache per glyph, eliminating the width>32K bounds mismatch that the intermediate refactor had introduced.
