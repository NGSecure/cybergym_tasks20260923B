While validating an ACE-prefixed domain label under TR46 rules, if the label has no characters left after the prefix (i.e. the portion to decode has length 0), libidn2's generic decoding routine still unconditionally reads byte 0 of the input array after finishing its delimiter scan, to check whether that position is a delimiter, without first checking whether the input length is 0 -- so that read lands on memory that was never written, triggering a use-of-uninitialized-value.
