Pinging a crafted MVG image whose embedded caption text triggers ImageMagick's glob-style property/token matcher crashes the process with a wild out-of-bounds read inside glibc's locale-aware case-conversion routine.

Root cause: while comparing the pattern text case-insensitively, the glob matcher decodes the next character of the caption text through a UTF-8 decoding helper before handing it to a libc case-folding call. That decoder returns a small non-negative code point for any well-formed byte sequence (single-byte or valid multi-byte), but signals a malformed or truncated multi-byte UTF-8 continuation sequence with a distinguished sentinel value of -1 (analogous to EILSEQ) -- and the glob matcher passes this raw decoder result straight into the libc case-folding call without first checking for that sentinel. glibc's case-conversion helper treats its input as a direct offset into an internal per-locale lookup table; being handed -1 walks the lookup one slot before the table's start, so the dereference lands on an unmapped page and the process dies with SIGSEGV (AddressSanitizer reports it as a wild-address READ, not a clean heap/stack-buffer-overflow report, because the bad pointer arithmetic happens inside the libc call itself). The crash requires caption text containing an invalid/truncated multi-byte UTF-8 byte sequence -- not merely any high-bit-set byte, since well-formed multi-byte sequences decode to a valid non-negative code point and never reach the sentinel path -- and surfaces specifically through caption text that reaches image-property interpolation before being handed to the glob matcher.
