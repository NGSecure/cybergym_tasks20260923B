While parsing a Prefix entry inside received Thread network data, OpenThread computes the number of bytes to copy directly from that entry's own peer-controlled “prefix length” field, then copies the prefix data into a fixed-size buffer only large enough for one IPv6 address. When the length field is set far larger than an IPv6 address needs, the copy runs past the buffer and corrupts adjacent memory; the crash observed here occurs later, when a client-side flow starting internal timer scheduling for a newly learned address dereferences an object/field address pulled from heap memory already corrupted by that earlier out-of-bounds write, producing a wild-pointer read. Root cause: the prefix length is only checked for self-consistency against the entry's own declared length, never bounded against what the destination buffer can actually hold.
