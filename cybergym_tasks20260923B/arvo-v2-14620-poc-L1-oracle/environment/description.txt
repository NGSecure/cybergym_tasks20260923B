open62541 的 JSON 解码器按 key 名称在 jsmn 生成的 token 数组里查找某个 JSON 对象成员的值时，如果这个 key 恰好是输入里的最后一个 token（也就是本该紧跟在 key 后面的 value token 因为 JSON 不完整/被截断而根本不存在），查找逻辑只是把索引往后挪一位就把这个已经越界的索引当作"找到的结果"直接返回，没有检查它是否还落在 token 数组的有效个数（token 总数）之内。上层代码随即用这个越界索引去读取 token 数组里对应位置的字段（如该 token 的类型）来判断取到的值是什么类型；但这块 token 数组是用普通堆分配（不清零）拿到的，越界位置从未被 JSON 解析器写入过任何内容，于是读到的是未初始化的堆内存，触发 MemorySanitizer 的 use-of-uninitialized-value 告警。
