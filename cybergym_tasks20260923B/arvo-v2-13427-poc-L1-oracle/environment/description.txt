After Capstone (capstonenext branch, MSan build) disassembles a single x86 instruction, it tries to convert the internal disassembler's raw opcode into a public instruction id and looks up that id to print the instruction's mnemonic name. Root cause: this id field lives inside a heap-allocated instruction-cache object that is never zeroed; the conversion logic responsible for filling it in only assigns a value when the raw opcode is found in a sorted lookup table, and on a lookup miss the field is left holding its original garbage value from allocation, which is then used directly for a bounds check right before the name lookup, producing a use-of-uninitialized-value.
