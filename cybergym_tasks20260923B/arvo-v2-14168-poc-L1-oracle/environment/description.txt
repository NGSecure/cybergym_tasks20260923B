FFmpeg's AGM (Amuse Graphics Movie) video decoder, when a non-key (inter/P) frame uses motion-compensated prediction, first parses a packed list of per-macroblock motion vectors into a heap array. That array's size is fixed once, sized from the macroblock grid implied by the dimensions the decoder was originally configured with. Later, while copying and predicting each 8x8 block of a color plane for that same frame, the decoder recomputes which motion vector applies to the current block using a different, coarser block grid — one derived from the width/height the current packet itself declares for its coded picture, and the container format allows that declared coded size to be padded up to a larger multiple-of-8 value than the decoder's originally configured size. When a packet's declared coded dimensions are pushed larger than the size the motion-vector array was originally allocated for, the block-to-motion-vector index computed from the packet's own (larger) grid can run one entry past the end of that array, and the decoder reads that out-of-range entry's coordinate field with no bounds check, producing a small heap out-of-bounds read at the tail of the array.
