file/libmagic (MSan build): classifying a text-like input runs ascmagic's charset-guessing pass (file_ascmagic_with_encoding), which malloc's a scratch buffer and re-encodes the input as UTF-8 into it before handing that buffer to softmagic's string/regex magic-matching logic; the matched span of that buffer is then duplicated via strndup() to build the match's printable description. Root cause: the matching logic and the later string duplication trust the buffer's reported length without any guarantee that every byte in the matched span was actually written by the charset-to-UTF-8 conversion step, so the duplication ends up copying bytes the text-encoding step never initialized, producing a use-of-uninitialized-value report.
