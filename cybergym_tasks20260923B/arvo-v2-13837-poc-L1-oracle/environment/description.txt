picotls's minicrypto PKCS#8 private-key ASN.1 parser (ASan build) suffers a heap-buffer-overflow read while recursively validating the algorithm-parameters element nested inside an embedded SEQUENCE. Root cause: when the preceding OBJECT IDENTIFIER field is parsed such that it consumes all (or more than) the bytes remaining in that SEQUENCE, the running byte offset ends up at or past the SEQUENCE's recorded end without that condition being checked; the size of the not-yet-parsed "parameters" region is then computed as an unsigned difference between the SEQUENCE end and that offset, which underflows to a huge value that gets handed to the recursive ASN.1 element parser as if it were a legitimate remaining length, letting it walk far outside the key buffer until it dereferences unmapped memory.
