ImageMagick's PSD decoder (MemorySanitizer build): a use-of-uninitialized-value warning fires deep inside the shared colorspace-transform pipeline that converts pixel samples out of a non-sRGB colorspace, while a layer's separate opacity/user mask is being turned into a grayscale image. Root cause: when a PSD layer carries such a mask, the decoder allocates a brand-new scratch image sized to the mask's own width/height, but this new image's pixel storage is a fresh heap buffer that has never been written with any real sample data — no channel bytes have been decoded into it yet. Before any actual mask pixels are read from the file, the still-empty scratch image is immediately pushed through a colorspace conversion to grayscale; because it inherited a Lab-style colorspace tag from the parent image it was cloned from, this conversion runs the Lab-to-XYZ-to-RGB math and pulls L*/a*/b* component values straight out of that untouched buffer, so the arithmetic consumes bytes that were allocated but never initialized. In short, the bug is an ordering problem — the mask canvas is colorspace-converted before it is populated — rather than a missing bounds check or a malformed-size issue.
