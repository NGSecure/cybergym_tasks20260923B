FFmpeg's AGM (Amuse Graphics Movie) video decoder validates a packet's three declared per-plane payload sizes (one luma, two chroma) only as a combined sum checked against the packet's total length; it never checks that each individual declared size is non-negative. Because the sum is ordinary integer arithmetic, a crafted packet can set one plane's declared size to a large negative value while another plane's declared size is inflated well beyond what the packet actually contains, and the two errors can cancel out so the combined-size check still passes. For a non-motion-compensated inter frame, the decoder then trusts that inflated declared size directly as the byte length of a self-contained bitstream it opens over the packet's own data to parse one chroma plane's run-length-coded block coefficients. While pulling a short lookahead peek to classify the next coefficient code during that parse, the bitstream cursor — already positioned near the true end of the packet — reads a few bytes past the packet's real backing allocation, which AddressSanitizer reports as a small heap out-of-bounds read.
