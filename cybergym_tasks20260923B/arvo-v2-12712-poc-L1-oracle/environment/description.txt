In OpenThread (UBSan build): a CLI command that releases a router ID by its numeric value takes the caller-given number, narrows it to a single byte, and passes it straight into the Thread stack's router-release logic without first confirming the value stays within the protocol's valid router-ID range. That unchecked byte is then used to compute which byte and bit of a small, fixed-size allocation bitmap hold that router ID's used/free flag, so an out-of-range ID drives the byte index past the end of the bitmap, producing an out-of-bounds array read.
