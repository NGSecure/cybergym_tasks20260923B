lwan (AFL HTTP request-parser fuzz target, ASan build): parsing a crafted HTTP request whose header section ends with a lone carriage-return byte positioned at the very end of the read buffer triggers a global-buffer-overflow read. Root cause: the header-line scanner locates that carriage-return byte with memchr and then, without first checking how many bytes remain before the buffer's end, uses an inline two-byte memcpy-based integer comparison to test whether the following byte is a line-feed; when the carriage-return is the very last byte in the fixed-size global scratch buffer holding the request data, that two-byte comparison reads one byte past the end of the buffer.
