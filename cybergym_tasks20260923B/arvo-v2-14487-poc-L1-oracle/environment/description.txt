Heap-use-after-free (8-byte read), reported by AddressSanitizer, while an OPC UA server instance is being torn down. The default access-control plugin's cleanup step releases a heap-allocated array of user authentication/token-policy entries; that same array had already been released once earlier, during an internal re-initialization of the server configuration, but the pointer describing it was never reset afterward. When the later teardown path frees it again, it goes on to walk the (already-freed) entries to release their string members, dereferencing memory that no longer belongs to the array — the double-free-turned-UAF read that AddressSanitizer flags.
